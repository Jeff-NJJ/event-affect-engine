# 表达层接入与验收

## 实现范围

`expression.py` 读取已有情绪状态，输出亲切、直接、轻松、展开程度、正式程度五项表达倾向。稳定基线来自人格及可选私有风格配置；混合情绪按连续强度叠加，沿用原有时间衰减。疲劳轻微改变展开程度。当前关系只小幅调整正式程度；对他人的不满不能直接等同于对当前对象不满。

这些系数是可调的表达设计，不是人类心理测量结果。“愤怒必说某词”“悲伤必用省略号”没有被当成规则。

口癖以 `when/avoid_when` 情境描述提供给云端回复模型。模型结合当前完整消息和历史决定是否使用；没有关键词语义分类。字面匹配仅用于判断某个明确口癖是否刚说过：最近两条使用过任何配置口癖，则本轮所有口癖候选冷却；同一口癖最近八条出现至少两次也冷却。只读准备、重试和查看快照均不消耗使用次数。手机和服务端重复历史不重复计数。候选冷却是确定性保证；最终生成仍是模型的软约束，不能宣称任意改写都被硬拦截。

第一轮云端实测发现完整示例被逐字照抄，且压过了情绪差异。最终配置仍可填写 `examples`，编译时只取句子平均长度等节奏信息；示例原句、场景事实不进入提示。此设计经本轮失败样例驱动调整。

## 服务端

本版发布号 `5.2.0`，情绪核心仍为 `affect-v5.1-research-v2`、schema 3，核心配置签名不变。已有 v5.1 数据无需重评迁移；生产升级仍应先备份、单写入者部署。v4/v5.0 依旧必须走原有迁移器，不能直接打开原库。本轮没有部署线上 5016。

可选环境变量：`EXPRESSION_PROFILES_FILE=/ABS/PRIVATE/expression_profiles.json`。参考 `deploy/expression_profiles.example.json`，按真实 `agent_id` 配置。没有文件时保留原角色风格，不凭空给角色添加口癖。错误文件在启动时显式拒绝。配置变动需重启服务；HTTP 来信不能修改此文件或人格。

只读接口：

```json
POST /v2/expression/context
{
  "agent_id": "example_agent",
  "actor_id": "example_user",
  "conversation_id": "真实会话ID",
  "source_event_id": "可选：已处理的来信事件ID"
}
```

沿用 `X-Token`。若传 source_event_id，必须确属当前角色、人物、会话且已应用，否则拒绝；未传则 `source_status=background_only`，不声称已分析当前来信。调用不创建事件、不调用分类模型、不生成或发送消息。响应含 `expression`、`prompt_suffix`、revision 和范围回执。可传最多八条 `recent_assistant`，仅做口癖使用计数，原始文本不拼入系统指令。

`endocrine_bridge.js` / `endocrine_api.js` 增加 `prepare_expression`，适合已经有稳定事件链的接入方：先分析真实来信并确认完成，再携带原 event_id 取表达提示，生成完成后用 `record_response` 记录真实正文。没有最终送达回执时不能冒充“已发送”。

## Operit 生成前注入

可导入 `operit/endocrine_expression_v1.toolpkg`。按固定源码 dbf71916fae9750cfdc9f9a774f5a0fee56633fb 的 `registerPromptFinalizeHook` / `before_finalize_prompt` 契约实现。未修改 APK。

手机私有 `.endocrine-client.json` 增加 `expression_routes`，示例见 `operit/expression_client.example.json`。每个路由必须精确匹配真实 chat_id 和角色卡 card_id，并明确 agent_id、actor_id。没有绑定的聊天不请求服务；角色组不自动猜测说话者，暂不注入。旧配置没有 expression_routes 时是未绑定状态。不要把示例占位 ID 当真实 ID。

钩子仅处理 CHAT 的生成前阶段，保留原 systemPrompt、用户全文、历史和工具参数。注入重复执行时替换自己的旧块，不叠加；更换角色或接口出错时移除可识别的旧块并记录状态。密钥由 Python 从本地配置读取，不进入模型提示、命令参数或报告。HTTP 子进程总时限四秒，拒绝重定向，不转发凭据。Operit hiddenExec 上限 6.5 秒；上游整个钩子链默认共享十秒，其他插件占用也可能导致跳过，不能保证每次注入。

本钩子只读取已有状态。它没有可靠的当前来信稳定 ID，因而没有自动创建分类事件，也没有增加第二条回复生成链。当前消息的上下文仍交给原回复模型理解；已有情绪状态提供背景。若需要保证当前来信先分类再生成，应使用上面的显式事件链或继续接入真实消息生命周期，不能用文本哈希假装消息 ID。

## 代理验收

不要求直连手机。导入后启用工具包及验收子包，调用 `endocrine_expression_probe_v1.probe`，参数为真实 chat_id、card_id。输出只包含状态、范围、注入字符数和时间，无 Key、无提示正文。此测试调用同一个钩子函数与真实 hiddenExec，仅验证原生函数路径和传输；仍要在实际聊天的模型请求中确认注入块出现一次。

实际聊天核对：

1. 对已绑定聊天确认模型请求保留原角色提示，表达块只出现一次；metadata 状态为 injected。
2. 切换未绑定角色/聊天，不应串用另一人的表达块；摘要、工具专用提示不应注入。
3. 进行多轮自然聊天，确认口癖不是每句必有；已说过口癖后不连续换另一个口癖。
4. 用相同任务分别设置愉快、失落、混合情绪，观察语气差异，同时检查事实和承诺是否一致。
5. 精确 JSON/代码输出、坏消息和反讽场景仍按全文语义处理；不能为了情绪破坏格式。
6. 不启动任何重复发送路径。此包的 probe 和表达接口均不调用发送接口。

本地验证使用 Node 契约、实际生成的 Python 子进程、临时 SQLite 与 loopback HTTP；不等于 Android 真机已验证。第三轮通过的是旧桥接验收，不能直接算成本次新钩子的真机结果。

## 云端样本与边界

`tools/evaluate_expression.py` 提供八个合成场景。首轮为无表达层与有表达层各一次，未固定采样种子，因此只能观察样本，不能据此宣称统计优越。后续修改保留所有失败报告。中途出现连续 HTTP 429；`reports/expression_cloud_final.json` 是该阶段的失败记录，不是最终验收报告。接口恢复后，最终代码八个场景均返回结果，记录在 `reports/expression_cloud_acceptance.json`，含 expression.py 的哈希。

最终内容审查仍观察到两处限制：开放式休息讨论回复偏长；反讽样例补写“刚才没接住你的反话”，而样例没有提供此前助手误解的记录。它们不影响只读接口和冷却逻辑的确定性验证，但说明表达软提示不能保证所有生成都自然且有据。不要把“八次请求完成”写成“内容质量八项全部通过”。

参数示例（凭证只放环境变量或私有文件）：

```text
python tools/evaluate_expression.py --report /ABS/NEW_REPORT.json --variants expression
```

使用 `CLASSIFIER_ENDPOINT/MODEL/KEY` 和 `CLASSIFIER_REQUEST_OPTIONS_JSON`；思考模型需足够输出预算和实际支持的选项。该脚本只做合成文本评测，正常产生供应商用量，不修改生产数据库。
