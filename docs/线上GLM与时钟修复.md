# 云端输出、超时与时间协议（v5.1）

v4.1 现场问题由用户提供：GLM 围栏 JSON、思考消耗 600 token、19–28 秒延迟、客户端漂移。本版保留相应保护，未改动线上 5016。

| 层 | v5.1 设置 |
|---|---|
| 模型输出 | 4096 token，多事实输出仍可能截断，截断显式失败 |
| 分类 | CLI 总截止 60 秒，包含最多 20 秒旧前情检索和两轮云端理解；单独分类配置范围 30–60 秒 |
| 传输 | 独立子进程硬截止，包含响应滴流；内层不再暗中截为 30 秒 |
| 处理租约 | 120 秒，token 防止旧持有者提交 |
| submit | 75 秒，预算不够开始新分类则 202 pending |
| 手机 | 单次 90 秒，最多两次，相同事件 ID 和正文；隐藏终端 190000ms |
| 云端全文检索 | 单次调用最多 60 秒、整个检索 75 秒，失败不返回伪完整结果 |

围栏解析支持整个 JSON 外侧的 json/JSON/无语言围栏和 BOM；不从任意解释文本中猜 JSON。空正文、finish_reason=length、损坏结构分别记录。新结构必须是 facts 数组，不退回关键词分类。日志不输出 Key、消息正文或推理正文。

旧 /emotion 与新 /v2/messages 可省略时间，服务器在防重事务内固定首次时间。带 occurred_at 的首次事件仍拒绝超前服务器 300 秒以上；GET /v2/time 返回可信服务时间。可显式提交 clock_sync={client_at_sync,server_at_sync} 校正偏差，payload.clock_audit 保留原时间与样本；如提供 observed_at，也按同一客户端时钟偏差校正并保留 original_observed_at；重试复用原请求及样本，不能悄悄改写已录入事实。

occurred_at 表示世界发生时间，observed_at 表示首次得知时间。默认 live 的旧事实按当前首次得知处理；明确 ingestion_mode=historical_replay 才以旧观察时间计算残余。原始接收墙钟与逻辑推进时间分离，系统时钟回拨不让新消息凭空老化。

火山方舟实测发现：不关闭思考时，复杂分类可能超过 30 秒；不能因为简单连通测试快就把分类超时改回 6 秒。供应商额外参数通过 CLASSIFIER_REQUEST_OPTIONS_JSON 配置，只传已验证支持的字段。/health 只反映进程和存储存活，不代表模型可用；查看分类状态和独立的真实验收结果。

分类采用草稿—语义审查两阶段，两次调用不分别重置 60 秒。恢复重试只追加一次理解记录；没有通过审查的草稿保留未知，不产生临时的强烈关系更新。
